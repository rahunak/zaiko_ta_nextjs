## 2. Находки: флоу записи (клиент)

**F1 · P0 · Мастер не получает уведомление о новой онлайн-записи.**
`sendTelegramMessage` вызывается только из `lib/dikidi/sync.ts` (изменение/отмена в DIKIDI) и
`lib/notifications/reminders.ts` (напоминание за 60 минут). В `app/book/actions.ts` уведомления нет.
Если флаг `book_sync_dikidi` выключен (по умолчанию), запись появляется только в БД — мастер узнаёт
о ней, лишь открыв расписание. Это главный риск потери клиента.

**F2 · P0 · Двойная отправка формы и двойное бронирование.**
Кнопка «Записаться» не блокируется на время отправки (`useFormStatus`/pending нигде не используется) —
двойной тап на мобильном создаёт две записи. На сервере проверка слота и вставка не атомарны
(check-then-insert без транзакции и без ограничения на пересечение интервалов), поэтому два
одновременных запроса на один слот могут оба пройти.

**F3 · P0 · Нет согласия на обработку персональных данных.**
Форма собирает имя и телефон, но нет чекбокса согласия и нет страницы политики (роутов `/privacy`
или `/terms` в `app/` нет). Для РБ это Закон «О защите персональных данных» 99-З; для Яндекса/Google
это ещё и требование к рекламным формам.

**F4 · P0 · Два источника правды по услугам и ценам.**
Лендинг берёт услуги из `lib/data.ts` (5 позиций, ламинирование «50 BYN»), `/book` — из таблицы
`services` (12 позиций). Расхождения: на сайте нет «Ваксинга», «Осветления бровей», «Ламинирования
верхних и нижних ресниц» (60 BYN) — при этом в записи они есть. В БД к тому же дубль-пара с опечаткой:
«Коррекция и окрашивние бровей» и «Окрашивание и коррекция бровей» — опечатка видна клиенту в `/book`.

**F5 · P1 · Клиент не получает ни подтверждения, ни напоминания.**
После записи показывается «Запись №N создана. Мастер свяжется с вами» — без даты, времени, услуги,
цены и без способа отменить/перенести. Напоминания настроены только мастеру.

**F6 · P1 · Нет минимального времени до записи и буфера между процедурами.**
Можно записаться на слот через 5 минут; `generateSlots` ставит записи вплотную — без 10–15 минут
на уборку/подготовку.

**F7 · P2 · Напоминание мастеру может потеряться молча.**
`sendTelegramMessage` глотает ошибки, но `sendDueReminders` всё равно ставит `reminder_sent_at = now()`
→ при сбое Telegram напоминание не повторится.

## 3. Находки: админка

**F8 · P1 · Расписание не обновляется само.**
Мастер держит страницу открытой — новые записи появятся только после ручной перезагрузки
(`revalidatePath` в server action обновляет кэш, но не открытую вкладку). Push/поллинга нет.

**F9 · P1 · Ручная запись не проверяет наложение.**
`createAppointment` в `app/admin/actions.ts` вставляет строку без `isSlotAvailable` — можно молча
поставить две записи на одно время (в `/book` такая проверка есть).

**F10 · P1 · Нет отметки «не пришёл» и нет учёта оплаты.**
Есть только мягкая отмена. Значит нельзя посчитать фактическую выручку, средний чек, долю неявок.

**F11 · P1 · Нет клиентской базы и поиска.**
Истории по телефону нет: повторные клиенты не видны, дубли не ловятся, поиска по имени/телефону
в расписании нет, экспорта нет.

**F12 · P2 · Частичная блокировка дня ограничена одним интервалом.**
`master_schedule_overrides` умеет `is_working` + один перерыв. Заблокировать «14:00–16:00 личные дела»
можно только как «перерыв», и только один на день.

**F13 · P2 · Вход без ограничения попыток.**
Нет rate limit/lockout на `/admin/login` — пароль можно перебирать (есть только 300 мс задержка).

**F14 · P2 · Расписание синхронно зависит от DIKIDI.**
Страница `/admin/schedule` делает внешний запрос в DIKIDI (таймаут 20 с), затем синк и напоминания —
всё в обработке запроса. При проблемах DIKIDI расписание грузится медленно или упирается в таймаут.

**F15 · P2 · Поле `source` бесполезно как канал.**
И онлайн-запись (`/book`), и записи из журнала DIKIDI (`lib/dikidi/sync.ts`) пишутся как `source='admin'`,
хотя схема предусматривает `'dikidi'`. Расписание фильтрует `source = 'admin'` — каналы не посчитать.

## 4. Находки: сайт, аналитика, эксплуатация

**F16 · P1 · Конверсия «запись создана» не отслеживается.**
GA4/Метрика ловят клики (`dikidi_click`, `tel_click`, `whatsapp_click`…), но успешная запись
(`/book?booked=N`) события не отправляет. Нельзя ответить, какой канал приводит записи, а не клики.

**F17 · P2 · У `/book` нет собственных метаданных.**
Страница наследует тайтл и описание главной — в выдаче и соцсетях это выглядит как дубль лендинга.

**F18 · P2 · Нет служебных страниц и мониторинга.**
Нет `not-found.tsx`, `error.tsx`, `loading.tsx`; нет Sentry/аптайм-мониторинга; в проекте **0 тестов**
и нет CI-проверок перед деплоем.

**F19 · P2 · `/api/cron/reminders` открыт, если не задан `CRON_SECRET`.**
Секрет опционален — без него эндпоинт может дёрнуть кто угодно и разослать напоминания раньше времени.
`/api/availability` без rate limit (не критично, но легко нагрузить БД).

**F20 · P2 · Главная — целиком клиентский компонент.**
`app/page.tsx` помечен `'use client'` и тянет все секции — гидратируется весь лендинг, хотя интерактив
нужен только hero/floating CTA. Влияет на INP/TBT на мобильных.

## 6. Чего не хватает как продукта (сводно)

- Мастер узнаёт о записи только зайдя в админку — нет мгновенного уведомления и нет уведомления клиенту.
- Клиент не может сам перенести/отменить запись — всё через переписку.
- Нет листа ожидания и уведомления «освободилось окно».
- Нет клиентской базы: повторные визиты, любимая услуга, история — не видны.
- Нет денежной картины: выручка по периодам, загрузка, средний чек, доля неявок.
- Нет единого прайса: сайт и форма записи живут на разных данных.
- Нет страницы политики/оферты и согласия на обработку данных.
- Нет технической observability: ошибки, аптайм, тесты, лимиты.

  `cross_opportunity_matrix` → диагностика).

  `error is 1`; удаление за пользователем.
- Проверка сценариев с реальными Telegram/DIKIDI-ответами не выполнялась (внешние сервисы).
