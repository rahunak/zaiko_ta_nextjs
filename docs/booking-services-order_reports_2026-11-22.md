# Порядок услуг, ошибка телефона и прошлые даты в пикере — отчёт

**Проект:** `zaiko_ta_nextjs` · **Дата:** 2026-11-22

## 1. Ручной порядок услуг (сложная задача, спека утверждена)

**Проблема:** очередность карточек на `/book` задавалась `order by name` — мастер не мог изменить порядок.

**Сделано:**

| Файл | Изменение |
|---|---|
| `db/schema.sql` | `services.sort_order integer not null default 0`, `alter ... add column if not exists` для живой базы, однократный бэкфилл алфавитным порядком (повторный прогон не сбрасывает выбор) |
| `scripts/db-init.ts` | при сиде услуг проставляется `sort_order = index + 1`; при `on conflict` порядок не перезаписывается |
| `app/admin/(protected)/services/page.tsx` | новая страница «Услуги»: нумерация, цена/длительность, пометка неактивных, стрелки ↑/↓ |
| `app/admin/(protected)/services/actions.ts` | `moveServiceAction`: нормализация 1…N, перестановка одним `update ... from unnest(...)` |
| `app/admin/(protected)/layout.tsx` | пункт меню «Услуги» |
| `app/book/page.tsx` | `order by sort_order, name` |
| `app/admin/(protected)/page.tsx`, `appointments/[id]/page.tsx` | списки услуг в админке в том же порядке |

**Проверено:** после миграции порядок 1…12 = прежний алфавитный (Ваксинг первый), дублей нет; в браузере (сессия создана напрямую в `admin_sessions`, пароль и `.env` не читались, после теста сессия удалена): ↓ у первой строки → Ваксинг стал вторым и в админке, и на `/book` (первая карточка — «Долговременная укладка бровей (+окрашивание)»); ↑ вернул на место; крайние стрелки неактивны; повторный прогон `db/schema.sql` дважды подряд порядок не сбросил; `sort_order` в базе после перестановок — 1…12 без дыр. `tsc --noEmit` чист.

## 2. Ошибка телефона выкидывала на сцену 1

**Проблема:** при любой ошибке валидации серверный экшен делал `redirect('/book?error=…')` без данных — форма монтировалась заново: сцена 1, пустые поля, сброшенные услуги и время.

**Сделано:** `app/book/actions.ts` возвращает с ошибкой `name`, `phone`, `comment`, `services`, `date`, `time`; `app/book/page.tsx` передаёт их в `BookingForm` как `initial`; `BookingForm` открывается на сцене 2 (кроме `invalid_service`), восстанавливает выбранные услуги, слот (если он ещё свободен), поля и показывает плашку ошибки; телефон с `aria-invalid` подсвечен рамкой. Валидация телефона стала терпимее: допускаются точки, дефисы, скобки; правило — 9…15 цифр (`+375 (29) 111.22.66` теперь принимается).

**Проверено в браузере:** ввод `12345` → `/book?error=invalid_phone…`, сцена 2 активна, имя/телефон/услуги `12,2`/дата/время на месте, плашка «Введите корректный телефон.», рамка `rgb(192,57,43)`; ввод `+375 (29) 111.22.66` → запись создаётся (тестовая строка удалена из БД).

## 3. DatePicker позволял выбирать прошлые даты

**Сделано:** `components/BookingForm.tsx` — у скрытого `input[type=date]` появились `min={todayMinsk()}` и `max` = последняя доступная дата; ручной ввод даты раньше сегодняшней игнорируется (`v >= todayMinsk()`).

**Проверено:** `min = 2026-11-22`, `max = 2027-01-05`; попытка выставить `2026-11-01` не меняет выбранную дату (`2026-11-23`).

## 4. Персонаж в карточке успешной записи

В iframe карточки персонаж был крошечным (мобильные vh-размеры и сдвиг из основного макета).
Добавлен режим `?embed=1&card=1`: `html.card` — персонаж на всю высоту блока, без ограничений
`min(52vh, 92vw)`; ссылка в `app/book/page.tsx` обновлена. Сцена 206 px при блоке 205,5 px.

Вторым шагом — центровка: в текстуре 680×664 персонаж нарисован левее центра (справа пустое поле),
поэтому центрирование канвы давало сдвиг влево. В режиме `card` добавлен `transform: translateX(10.2%)`.
Проверено по пиксельному центру содержимого: 390 px — центр 137,5 при блоке 274 (было 115,5);
360 px — 121,5/122; 430 px — 157/157. Главная `/book` не изменилась (персонаж 91vh справа,
класс только `embed`).

## Ограничения

- Визуальная проверка нативного пикера недоступна автоматизации: проверены атрибуты `min/max` и реакция на ручной ввод.
- Тестовая запись в DIKIDI `1194647723` (23.11.2026 12:00, «ТЕСТ флаг synced») осталась — удаление через API отклоняется (`error is 1`), пользователь удаляет сам.
- Записи из `/book` попадают в DIKIDI только при включённом флаге в админке (см. предыдущий отчёт); в DIKIDI окно мастера уже́, чем локальное расписание сайта.
